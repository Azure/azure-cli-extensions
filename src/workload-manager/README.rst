Microsoft Azure CLI ``workload-manager`` Extension
==================================================

This package provides commands for managing Microsoft Compute Workload Manager resources.

Commands
--------

* ``az workload-manager workload-space``
* ``az workload-manager workload-space runtime-binding``
* ``az workload-manager workload-space runtime-link``
* ``az workload-manager workload-space capability``

Provision a complete workload space
----------------------------------

``az workload-manager workload-space up`` submits one incremental ARM deployment
containing the workload space, AKS and ACI runtime bindings, runtime link, and
AgentSandbox and PodSnapshotRestore capabilities. ARM serializes the resource
operations and continues after the CLI disconnects.

The resource group must already exist. Configure the required provider and feature
registrations and Workload Manager service permissions first; this command does
not register providers or grant roles. Use a region supported by the service.

Managed AKS and managed ACI are the default::

    az workload-manager workload-space up -g MyResourceGroup -n MySpace -l eastus2

To reference an existing AKS cluster, supply all three options together::

    az workload-manager workload-space up -g MyResourceGroup -n MySpace -l eastus2 --managed-cluster-resource-id <aks-resource-id> --workload-execution-subnet-id <aci-subnet-id> --runtime-link-subnet-id <link-subnet-id>

The AKS cluster must be in the selected subscription and region. Both subnets
must be in that subscription and the cluster's VNet. The runtime-link subnet
must be empty and distinct from the AKS and ACI subnets. AKS topology and other
service prerequisites are validated by the resource provider.

The child names are ``aks``, ``aci``, ``link``, ``agent-sandbox`` and
``pod-snapshot-restore``. Repeating the command targets these same resources and
reapplies the configuration, including tags. It does not adopt differently named
children or convert an existing binding between managed and referenced modes.
Incremental deployment preserves unrelated resources; failed deployments do not
automatically roll back resources already created.

``--deployment-name`` defaults to the workload-space name. The command returns
the ARM deployment result, including ``outputs.workloadSpaceId.value``.
Use ``--no-wait`` to return after submission and inspect progress with::

    az deployment group show -g MyResourceGroup -n MySpace

The template is generated by the extension and can be retrieved from the ARM
deployment for reuse in pipelines. The existing ``workload-space create`` command
continues to create only the parent resource.

Development sources
-------------------

The extension targets API version ``2026-11-01-preview`` from
`azure-rest-api-specs PR 46394 <https://github.com/Azure/azure-rest-api-specs/pull/46394>`_.
Its commands are generated from Azure AAZ command models.
